# AutoUBC - UI/UX Refactor: Navigation, Data Entry, Sync Indicator

## Overview
- **Summary**: Доработка навигации (сокращение вкладок и drill-down в детализацию недели), улучшение UX формы ввода данных (валидация, выравнивание) и переработка логики индикатора синхронизации в AppBar.
- **Purpose**: Упростить структуру главного экрана, убрать лишнюю вкладку истории по дням, исправить неудобную валидацию и сделать индикатор синхронизации менее шумным.
- **Target Users**: Пользователи AutoUBC (водители, ведущие учёт топлива и пробега).

## Goals
- Сократить вкладки нижней навигации с 3 до 2 (Ввод данных + Еженедельный отчёт).
- Реализовать drill-down: карточка недели → экран детализации дневных записей с редактированием/удалением.
- Исправить баг: после успешного добавления заправки поле не должно подсвечиваться красным.
- Центрировать чипы выбора топлива в блоке заправки.
- Реализовать 3 состояния индикатора синхронизации: скрыто по умолчанию, зелёный на 2 сек после успеха, красный — постоянно при ошибке.

## Non-Goals
- Не менять модель данных и схему Isar.
- Не менять провайдер локализации и языки (RU/UK/EN).
- Не трогать сервисную книжку, напоминания и экспорт отчётов.
- Не менять логику вычислений еженедельного отчёта (расчёты, приоритет недель).

## Background & Context
- Текущая структура: `main.dart` использует `PageView` на 3 страницы (индексы 0,1,2): 0=DataEntry, 1=HistoryScreen, 2=WeeklyReport.
- `HistoryScreen` (вкладка «История по дням») группирует одометр/заправки по датам месяца и позволяет удалять записи.
- `WeeklyReportScreen` рендерит карточки недель через `ListView.builder`, каждая карточка — `Card` без `InkWell`/`GestureDetector`.
- `DataEntryScreen` использует `GlobalKey<FormState>` для топлива с `AutovalidateMode.onUserInteraction` и явным `clear()` контроллера после сохранения, что триггерит валидацию.
- `SyncStatusIndicator` всегда отображается при подключённом Google Drive и использует `SyncStatus` (unknown/idle/syncing/error).

## Functional Requirements

### Навигация (Раздел 1 ТЗ)
- **FR-1**: Главный экран использует `PageView` на 2 страницы (Ввод данных, Еженедельный отчёт); `HistoryScreen` удалён из вкладок.
- **FR-2**: Карточка недели в еженедельном отчёте — кликабельна (InkWell/обёртка) и навигарует на экран детализации недели.
- **FR-3**: Экран детализации недели принимает `weekStart`/`weekEnd` (или week-подобную структуру) и показывает заголовок вида «Детализация: 7 - 13 сентября».
- **FR-4**: В детализации недели выводятся дневные записи (одометр + заправки) за выбранный диапазон дат, сгруппированные/отсортированные по дате/времени.
- **FR-5**: В детализации недели доступны удаление записей (и редактирование, если оно уже поддерживается историей).
- **FR-6**: При возврате с экрана детализации на еженедельный отчёт данные недели автоматически пересчитываются.

### Форма ввода (Раздел 2 ТЗ)
- **FR-7**: После успешного добавления заправки (нажатие «+») поле литров:
  1. теряет фокус (unfocus/clearFocus);
  2. очищается;
  3. рамка — нейтральная серая;
  4. ошибка «Заповніть поле» **не показывается**.
- **FR-8**: Красная рамка + «Заповніть поле» появляются **только** при попытке отправить пустую форму (нажатие «+» при пустом поле), а не при очистке поля после успешного сохранения.
- **FR-9**: Кнопки (OutlinedButton) видов топлива в блоке заправки центрированы по горизонтали относительно контейнера/поля ввода.

### Индикатор синхронизации (Раздел 3 ТЗ)
- **FR-10**: При синхронизации нет «нейтрального/серого» индикатора — по умолчанию индикатор **скрыт**.
- **FR-11**: После успешной синхронизации показывается **зелёный** индикатор, который автоматически исчезает через 2 секунды.
- **FR-12**: При ошибке синхронизации показывается **красный** индикатор, который горит постоянно, пока ошибка не будет снята следующей успешной синхронизацией.
- **FR-13**: Индикатор процесса синхронизации (синий/«syncing») — отображается во время активной синхронизации (поведение syncing-состояния).

## Non-Functional Requirements
- **NFR-1**: Не вводить новых зависимостей в `pubspec.yaml`; использовать Flutter, Provider, Isar, существующие утилиты.
- **NFR-2**: Сохранить работоспособность существующих тестов (`flutter test`); при необходимости адаптировать только тесты, которые напрямую затронуты.
- **NFR-3**: Переиспользовать существующие методы `AppProvider` (удаление логов, refresh) без дублирования логики.
- **NFR-4**: Локализация: все новые строки должны получаться из `AppLocalizations` (при необходимости добавить ключи в `.arb`-файлы).
- **NFR-5**: `flutter analyze` проходит без новых ошибок и предупреждений.

## Constraints
- **Technical**: compileSdk=35, Flutter 3.47+, Dart 3.13+, AGP 8.11.1, Gradle 8.14.1 (согласно project_memory).
- **Business**: Изменения только по ТЗ; не делать «косметику» сверх требуемого.
- **Dependencies**: Provider для state, GoogleDriveSyncService — для статусов синхронизации.

## Assumptions
- «Редактирование» в детализации недели означает как минимум удаление (как в HistoryScreen); отдельного редактирования полей (edit-диалога) в ТЗ явно не требуется, но если HistoryScreen уже умеет — сохранить.
- Сброс автодобавления/автовалидации поля литров можно выполнить через `FocusScope` + смену `AutovalidateMode` или сброс формы после очистки.
- Для «зелёный на 2 сек» достаточно временного флага в `SyncStatusIndicator` или `GoogleDriveSyncService`/`MainScreen` AppBar, управляемого `Timer`.
- «Ошибка» синхронизации берётся из существующего `hasSyncError` / `SyncStatus.error`.

## Acceptance Criteria

### AC-1: Главный PageView имеет ровно 2 вкладки
- **Type**: `rule`
- **Given**: Запущено приложение с выбранным автомобилем.
- **When**: Пользователь свайпает или наблюдает индикаторы страниц (точки внизу).
- **Then**: Всего 2 точки-индикатора; при свайпе доступны только «Ввод данных» и «Еженедельный отчёт».
- **Pass Condition**: В коде `_totalPages == 2` и switch `_getRealIndex` имеет case 0,1 без HistoryScreen.
- **Evidence**: `main.dart` + `flutter run` — 2 индикатора.

### AC-2: Карточка недели нажимается и ведёт в детализацию
- **Type**: `rule`
- **Given**: Открыта вкладка «Еженедельный отчёт» и есть хотя бы одна прошедшая/текущая неделя.
- **When**: Пользователь нажимает на карточку недели.
- **Then**: Открывается экран с AppBar «Детализация: …» и списком записей за эту неделю.
- **Pass Condition**: Картка обёрнута в `InkWell`/`GestureDetector`; `Navigator.push` создаёт `WeekDetailScreen` (или эквивалент) с параметрами недели.
- **Evidence**: `weekly_report_screen.dart` + визуальный осмотр экрана.

### AC-3: Детализация недели показывает и позволяет удалять записи
- **Type**: `rule`
- **Given**: В неделе есть одометр/заправки.
- **When**: Пользователь прокручивает детализацию и нажимает delete-иконку у записи.
- **Then**: Показывается диалог подтверждения; после подтверждения запись удаляется из БД и списка.
- **Pass Condition**: Список отфильтрован по `weekStart..weekEnd`; вызовы `AppProvider.deleteOdometerLog` / `deleteFuelLog` присутствуют.
- **Evidence**: Код экрана детализации + удаление из UI триггерит исчезновение строки.

### AC-4: Возврат из детализации → пересчёт карточки недели
- **Type**: `rule`
- **Given**: В детализации удалена запись, влияющая на итог недели.
- **When**: Пользователь нажимает «Назад».
- **Then**: Карточка недели на еженедельном отчёте показывает обновлённые значения (расстояние, литры).
- **Pass Condition**: `setState` или `refreshAll`/пере-сборка FutureBuilder при возврате (например, `await Navigator.push(...) → setState((){})`).
- **Evidence**: Вручную изменить, вернуться, сравнить числа.

### AC-5: Поле литров — нет ошибки после успешного «+»
- **Type**: `rule`
- **Given**: Экран «Ввод данных», поле литров валидно (например, «10»).
- **When**: Нажать «+», получить SnackBar об успехе.
- **Then**: Поле очищено, рамка — серая (не красная), нет текста «Заповніть поле», фокус не в поле.
- **Pass Condition**: После save происходит `unfocus` + controller очищается без валидации; `AutovalidateMode` не триггерит ошибку при пустом значении из-за очистки.
- **Evidence**: `data_entry_screen.dart` + ручной прогон.

### AC-6: Ошибка «Заповніть поле» — только при submit пустого поля
- **Type**: `rule`
- **Given**: Поле литров пустое.
- **When**: Нажать «+» при пустом поле литров.
- **Then**: Рамка — красная, сообщение «Заповніть поле» видно. Когда пользователь просто очистил поле после предыдущего успешного сохранения (без submit), ошибки нет.
- **Pass Condition**: `_fuelFormKey.currentState?.validate()` вызывается только при «+»; очистка контроллера сама по себе не триггерит ошибку.
- **Evidence**: `data_entry_screen.dart` + ручной прогон.

### AC-7: Чипы топлива центрированы
- **Type**: `rubric`
- **Dimension**: Выравнивание UI-элементов
- **Scale**: 1-3
- **Anchors**: 1 = чипы выровнены по левому краю, визуально смещены; 2 = центрированы примерно, но есть небольшой сдвиг; 3 = чипы строго центрированы по горизонтали относительно поля и контейнера Card.
- **Pass Threshold**: >= 3
- **Evidence**: `data_entry_screen.dart` — `Wrap`/`Row` с `alignment: WrapAlignment.center` или эквивалент + скрин/визуальная проверка.

### AC-8: По умолчанию индикатор синхронизации скрыт
- **Type**: `rule`
- **Given**: Google Drive подключён, синхронизация idle и без ошибок.
- **When**: Пользователь смотрит на AppBar рядом с названием автомобиля.
- **Then**: Никакого круглого индикатора (серого/зелёного) нет.
- **Pass Condition**: `SyncStatusIndicator` возвращает `SizedBox.shrink()` или не рендерится в idle/unknown.
- **Evidence**: `sync_status_indicator.dart` + ручной осмотр.

### AC-9: Зелёный индикатор успеха исчезает через 2 сек
- **Type**: `rule`
- **Given**: Активна синхронизация (upload/download).
- **When**: Синхронизация завершилась успешно.
- **Then**: Показывается зелёный индикатор; через ≈2 сек он исчезает.
- **Pass Condition**: Timer(Duration(seconds:2)) выставляет временный visible=false после idle success.
- **Evidence**: Код индикатора (таймер) + ручная проверка с синхронизацией.

### AC-10: Красный индикатор ошибки — постоянный до успеха
- **Type**: `rule`
- **Given**: Синхронизация завершилась с ошибкой.
- **When**: Проходит 2, 5, 10+ секунд.
- **Then**: Красный индикатор остаётся видимым до следующей успешной синхронизации, после чего переходит в сценарий AC-9 (зелёный 2 сек → скрыт).
- **Pass Condition**: Ошибочное состояние не имеет таймера авто-скрытия; только успешный финал запускает таймер зелёного → скрыть.
- **Evidence**: `sync_status_indicator.dart` + `google_drive_sync_service.dart` (hasSyncError).

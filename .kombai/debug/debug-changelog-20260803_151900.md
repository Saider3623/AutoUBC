## Changes Made

### 1. Added durable Drive baseline metadata
- **File:** `lib/services/google_drive_sync_service.dart`
- **Change:** Persisted a stable remote fingerprint (`md5Checksum`, falling back to Drive `version`) alongside the existing modified timestamp and account key.
- **Why:** A Drive `modifiedTime` can be serialized with different precision between sessions, causing false startup conflicts.
- **Revert:** Remove `_lastRemoteFingerprintKey`, `_lastKnownRemoteFingerprint`, fingerprint persistence/loading, and the fingerprint fields from the startup decision.

### 2. Made startup comparison resilient while preserving real conflicts
- **File:** `lib/services/google_drive_sync_service.dart`
- **Change:** Prefer matching fingerprints; for legacy timestamp-only installations, accept a maximum two-second timestamp difference. Keep `conflict` for different fingerprints or larger timestamp differences. Migrate confirmed timestamp-only baselines to fingerprint metadata.
- **Why:** Prevent repeated false-positive dialogs without silently accepting a changed cloud backup.
- **Revert:** Restore exact timestamp equality as the only baseline comparison and remove the migration branch.

### 3. Improved conflict failure feedback
- **File:** `lib/main.dart`
- **Change:** Show a localized error SnackBar when startup restore, conflict restore, or conflict upload does not complete successfully.
- **Why:** A failed resolution must not look like a completed sync while leaving the dialog eligible on the next launch.
- **Revert:** Remove the failure SnackBar branches.

### 4. Added regression coverage
- **File:** `test/google_drive_sync_logic_test.dart`
- **Change:** Added tests for timestamp precision tolerance, matching/mismatched fingerprints, and Drive fingerprint extraction.
- **Why:** Lock in the false-conflict fix and protect real conflict detection.
- **Revert:** Remove the new tests and helper assertions.

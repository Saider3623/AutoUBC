## Changes Made

### 1. Serialized DatabaseService initialization
- **File:** `lib/db/database_service.dart`
- **Change:** Added `_initialization` and `_closeFuture` guards so concurrent reads share one Isar initialization and reads wait while the database is closing.
- **Why:** AppProvider initialized the database in its constructor while startup sync called `loadCars()` again. A download could therefore race with an active Isar open/read.
- **Revert:** Remove the two lifecycle futures and restore the original `isar` getter and `close()` implementation.

### 2. Made database close await pending initialization
- **File:** `lib/db/database_service.dart`
- **Change:** `close()` now waits for a pending open, clears `_isar`, closes the captured instance, and prevents duplicate close operations.
- **Why:** The downloaded file must never be swapped while an Isar instance is still opening or serving an initialization backup.
- **Revert:** Restore the previous direct `await _isar?.close()` implementation.

### 3. Exposed and awaited AppProvider startup initialization
- **Files:** `lib/providers/app_provider.dart`, `lib/main.dart`
- **Change:** AppProvider stores its constructor-triggered `loadCars()` future as `initialization`; cloud startup awaits that future instead of starting a second concurrent `loadCars()` call.
- **Why:** Prevents duplicate startup reads and ensures the decision to download/upload uses the completed local state.
- **Revert:** Remove the `initialization` future and restore `await appProvider.loadCars()` in `_initializeCloudSync`.

### 4. Added lifecycle regression test
- **File:** `test/database_service_lifecycle_test.dart`
- **Change:** Verifies that the database can be closed and reopened through the singleton service. Skips only when native Isar or application storage is unavailable in the test runner.
- **Revert:** Delete the test file.
